# 糖糖 V3 架构迁移实施计划

## 目标

在不破坏当前可运行 `code/cat/` 系统的前提下，逐步把现有脚本迁移为清晰的家庭 AI 架构。

## 新旧兼容

第一阶段不删除、不重命名旧 `cat-*` 脚本。新模块通过适配层调用旧能力，验证稳定后再迁移。

## 模块职责

| 模块 | 负责 | 不负责 |
|---|---|---|
| family | 身份、成员、权限、偏好 | 记录行为结论 |
| memory | 事件、记忆、趋势、习惯 | 决定是否说话 |
| context | 构建最小 AI 上下文 | 修改原始数据 |
| behavior | 打扰决策、策略、冷却 | 生成最终音频 |
| interaction | 编排一次互动 | 保存敏感长期数据 |
| presentation | TTS、动作、媒体、投影 | 判断用户是谁 |

## 第一阶段：骨架

- 建立目录与接口说明
- 建立 runtime context schema
- 建立事件模型
- 建立响应协议
- 保留旧系统作为 fallback

## 第二阶段：接入

- voiceprint → family.IdentityResolver
- voice/STT → interaction.Input
- family + memory → context.ContextBuilder
- behavior.ShouldInterrupt → 主动提醒入口
- LLM → TANGTANG_RESPONSE
- presentation → action/media registry

## 第三阶段：验证

每迁移一个入口必须通过旧链路回归测试与新链路测试。

## 第四阶段：清理

只有在至少一个完整家庭场景连续稳定运行后，才允许重命名 `cat-*` 和删除重复实现。

## 禁止事项

- 不把真实家庭数据提交 GitHub。
- 不让 LLM 直接写长期记忆。
- 不让 LLM 执行 shell。
- 不让 unknown 自动绑定成员。
- 不为了测试通过而修改测试标准。
