# 糖糖任务与承诺服务 V1

## 目的

`core/tasks/service.py` 是本地任务状态服务，供语音入口、定时器、后续 Web 控制台复用。它不是聊天模型，也不是调度器。

它负责“任务是否存在、归谁所有、何时到期、状态是什么、是否完成/取消”；它不负责“到时间实际播放声音、推送通知，并确认送达”。

## 当前能力

- 任务类型：`reminder`、`follow_up`、`commitment`、`task`
- 状态：`proposed`、`needs_confirmation`、`scheduled`、`running`、`done`、`failed`、`cancelled`
- ISO 8601 到期时间必须包含时区偏移，避免“明天九点”被错误解释成 UTC。
- `idempotency_key` 用于防止重复请求创建同一事项。
- 默认 PRIVATE；FAMILY 事项只对登记的家庭成员可见；私人事项其他成员不可读取。
- 生产存储在 `$TANGTANG_HOME/tasks/tasks.json`（或 `TANGTANG_DATA_DIR` 对应根目录下）。
- 所有持久化由原子临时文件替换写入；任务元数据禁止包含语音转写、原话、音频、声纹等字段。

## Python 使用示例

```python
from core.tasks.service import TaskService

tasks = TaskService(
    home="/path/to/TangTangData",
    persist=True,
    members=family_members,
)

task = tasks.create_task(
    owner_member_id="dad",
    title="准备明天的材料",
    due_at="2026-10-15T09:00:00+08:00",
    timezone_name="Asia/Shanghai",
    kind="reminder",
    visibility="PRIVATE",
    idempotency_key="prepare-materials-2026-10-15",
)

due = tasks.due_tasks(
    now=current_aware_datetime,
    viewer_id="dad",
)

# 仅在实际发送提醒成功后，才调用 complete/mark_attempt 或写入送达结果。
tasks.mark_attempt(
    task.task_id,
    owner_member_id="dad",
    result="delivered",
)
```

## 行为约束

1. 解析出的日期或时间不明确时，调用方应先让用户确认，不得虚构时间。
2. `create_task` 成功只意味着任务保存成功，不代表提醒已创建于操作系统，也不代表已送达。
3. 一个稳定的幂等键对应一个任务；重试创建不会生成多个重复任务。
4. 只有任务所有者能改期、完成、取消或记录执行尝试。
5. 已完成的任务不可取消；已取消或已失败的任务不能直接标记完成，失败任务需要显式改期后再安排。
6. FAMILY 任务只能由当前登记成员读取；PRIVATE 任务只对所有者可见。
7. 不要把完整聊天记录放入标题或 metadata；metadata 不接受 transcript / speech / utterance / raw 等字段。
8. 下一个工程阶段再接入调度器与实际 TTS 通知入口，并为“到期—触发—播报成功/失败—恢复重试—用户取消”编写集成测试。
