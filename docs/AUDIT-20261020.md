## 已确认的问题

### P1 — `cat-voice-chat.sh` 曾不是语音对话入口

该文件与 `cat-talk.sh` 内容相同，实际执行的是事件话术与 TTS，不会录音、STT 或调用 `cat-chat.py`。这与报告中“语音对话入口已完成”的描述不一致。

**本次修复：** 将 `cat-voice-chat.sh` 改为校验参数后转交给已有的 `cat-voice.sh` 语音对话实现；新增 `tests/v4/test_voice_entrypoint.py` 防止入口再次被事件发声逻辑覆盖。

**尚需设备验证：** 在家庭 Mac 上测试麦克风索引、录音、百度 STT、LLM、TTS 和实际播放设备。仓库静态审计不能代替硬件实测。

### P1 — CI 测试契约与当前 `cat-chat.py` 不一致

当前 `tests/v4/test_voice_cli_wiring.py` 引用了 `cat-chat.py` 中的 `_runtime_llm`、`_llm_timeout_seconds`、`_local_safety_reply` 等接口；当前仓库版本的 `cat-chat.py` 未定义这些接口，而是另一套较早的命令行实现。因此，至少这部分 V4 测试与当前代码存在明确的契约不匹配，不能把冒烟报告的 PASS 当作 CI/V4 全绿。

**处理原则：** 不直接把旧文件整体覆盖成猜测版本。需要根据 V4 runtime 的当前调用契约恢复/整合对话桥接，同时保留最近增加的人设记忆注入、风险拦截、隐私边界和对话历史限制，再运行完整测试集。

### P2 — 冒烟测试范围与可移植性有限

`tests/smoke-20261019.sh` 依赖 macOS 的 `stat -f`、`launchctl` 和 `/usr/bin/python3`，并检查本机 `~/tangtang/cat` 运行目录。它适合作为家庭 Mac 部署后检查，但不是通用 CI 测试，也没有运行 `tests/v4/run.py`。

### P2 — 零漂移检查会跳过缺失文件

第 9 节比较仓库文件与 live 文件时，遇到 live 中不存在的文件会直接 `continue`，所以“PASS 零漂移”不等于所有应部署文件均已部署。关键文件列表只覆盖少数脚本，仍可能漏掉新依赖。

### P2 — 部署目标路径不一致

冒烟脚本支持 `TANGTANG_LIVE_DIR`，但 `code/cat/deploy.sh` 固定写入 `$HOME/tangtang/cat`。在自定义运行目录下执行时，测试目标和部署目标可能不同。
