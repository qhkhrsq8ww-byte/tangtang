# 糖糖升级为生活伙伴：架构收口路线图 V1.0

日期：2026-10-14

## 一、结论

糖糖不需要推倒重写 V4。下一阶段的主要工作不是增加更多功能，而是把现有模块收口成一条稳定、可恢复、可审计的生活服务闭环：

**输入 → 身份与授权 → 安全路由 → 事件 → 记忆检索 → 决策 → 任务/行动 → 表现 → 结果回写。**

当前已有 IdentityResolver、PrivacyPolicy、PrivacyPipeline、ContextBuilder、InterruptPolicy、ResponseOrchestrator、TTSAdapter、ProjectionAdapter、AnimationController 等基础组件。存在的主要问题是这些能力尚未全部进入同一条生产链路，且 CLI、旧版生活脚本、V4 Runtime 各自承担部分业务。

原则：先修高风险边界，再解决记忆的真实持久化和检索，之后统一任务与行动；不另起一套全新框架。

## 二、当前架构审计结论

| 等级 | 发现 | 影响 |
|---|---|---|
| P0 | 未知身份被划分为 PUBLIC；对话适配器原先只阻止 PRIVATE 云端调用 | 无法确认说话者时，原话可能被发送到模型网关 |
| P0 | 风险关键词遗漏“欺负/被欺负”等常见求助表述，且安全标记没有成为所有入口统一的强制路由 | 私密内容可能被隔离，但即时安全响应与家长提醒不一定触发 |
| P1 | Runtime 默认构造的 EventStore/部分 Memory Store 是内存实例 | 独立 CLI 进程结束后，部分状态无法恢复 |
| P1 | PrivateMemory 有写文件逻辑，但没有与之匹配的启动加载/过期清理完整生命周期 | 落盘不等于下次对话可以回忆 |
| P1 | LearningMemoryService、FamilyMemoryV2、旧版 cat-family/cat-habits 与 V4 Stores 并存 | 多套记忆源可能不一致；上下文构建未统一读取它们 |
| P1 | 闹铃、今日四步、主动场景与 V4 打扰策略并行 | 任务结果、重复提醒、冷却和取消行为没有统一事实来源 |
| P2 | 大量功能以 CLI 为入口，缺少家人可检查/修正/删除记忆的统一控制面 | 用户难以理解系统记住了什么、任务是否成功以及如何撤销 |

## 三、安全与隐私的短期规则

1. **未知身份不是云端授权。** 未识别说话者的原话默认本地处理，Event payload 与普通日志只保留脱敏标记。需要访客云端对话时，由家庭显式配置 `TANGTANG_ALLOW_UNKNOWN_LLM=1`。
2. 已确认儿童身份的发言仍按 PRIVATE 处理；`TANGTANG_ALLOW_PRIVATE_LLM=1` 仍然是独立、明确的本地 opt-in，不能由 unknown 开关替代。
3. 风险词表是第一道确定性拦截，不等同于完整安全分类。下一步要把 SafetyRouter 放入所有语音、文本、定时/环境事件入口，并将严重风险从普通打扰冷却中分离。
4. 安全提醒日志仅记录类别、时间、成员引用和事件引用，不记录儿童原话。普通的同伴冲突需要支持和澄清，不应所有事件都被错误升级为紧急情况。
5. 家庭、个人、PRIVATE 数据拥有独立的查看权限、保留期限、删除路径。未经授权，不把私人对话转成家庭趋势、家长摘要或训练数据。

## 四、目标架构

```text
Mic / CLI / Timer / Living-room observation / Web
                      |
             Input Normalizer
                      |
            Identity + Confidence
                      |
             SafetyRouter + PrivacyPolicy
                      |
             Canonical Event Service
                      |
        Memory Manager + Task/Promise Store
                      |
             Bounded Context Builder
                      |
       Deterministic Policy + LLM Planner
                      |
              Action Executor
                /           \
      Reminders/Calendar     Presentation
      Weather/Local tools    TTS/Animation/Projection
                \           /
              Outcome Recorder
                      |
                  Event Store
```

架构约束：

- `TangTangRuntime` 是唯一生产编排入口；旧脚本逐步改成薄适配器，不允许在其中重复实现隐私和决策规则。
- 模型可以理解、总结、提议行动，但不能直接访问文件系统、Shell、硬件或原始存储。
- 行动执行器只接受 schema 校验通过的动作，按风险级别执行；不可逆、对外发送或高影响动作必须确认。
- 一个事件只能有一个权威持久化入口；家庭状态、趋势、摘要是从事件派生的可重建视图，不做互相独立的事实库。
- 表现层只执行结构化动作与文案，不决定身份、隐私或是否应该打扰。

## 五、记忆 V2：从“写文件”到“能被正确回忆”

先统一接口与生命周期，再决定底层是否迁移到 SQLite。第一轮不必引入复杂基础设施。

### 记忆类型

- **偏好**：称呼、喜欢/不喜欢的活动、语音与提醒偏好。
- **约定/承诺**：糖糖答应的事、家庭约定、下次需要跟进的事。
- **任务事实**：事项、负责人、到期时间、状态和执行结果。
- **近期情境**：本次互动中需要短期使用的信息，带 TTL。
- **私人经历**：仅本人可访问；默认不过度保存原话。
- **习惯趋势**：仅保存足够证据支持的标签、计数与时间窗口，不给人贴人格标签。

### 每条记忆必须具备

`memory_id`、`member_id`、`kind`、`data`、`privacy`、`source_event_ids`、`confidence`、`created_at`、`expires_at`、`retention_policy`。

写入必须有规则或用户明确授权。大模型不能自行决定把任意聊天永久保存。读取时根据当前查看者和数据范围过滤，不允许先读取再靠 prompt 要求模型忽略隐私。

### 必须实现的生命周期

1. 进程启动时加载或索引已保存的记忆。
2. 事件/记忆写入具备去重、原子写入与失败记录。
3. 查询接口同时提供本人、家庭共享和到期任务视图。
4. 到期清理真实删除已过期数据；用户可以修正和删除记忆。
5. 记忆迁移有版本号、备份、回滚与数据核验。
6. 测试进程重启后的读取、权限隔离、TTL、删除和重复事件，而不只测试同一进程里的对象。

## 六、任务与承诺层

生活伙伴区别于聊天机器人的关键，是它能可靠跟进事情。

统一任务结构至少包括：

- `task_id`、`owner_member_id`、`kind`、`title`
- `due_at`、`timezone`、`status`、`priority`
- `source_event_id`、`created_by`、`consent`
- `idempotency_key`、`last_attempt_at`、`result`
- `created_at`、`updated_at`、`cancelled_at`

状态至少有 `proposed`、`needs_confirmation`、`scheduled`、`running`、`done`、`failed`、`cancelled`。

语义要求：

- “明天提醒我准备东西”若时间不够明确，应先询问或给出确认项，不能假装已成功创建提醒。
- 工具执行成功后才能向用户说“已经设置好”。
- 超时或进程重启后可恢复执行，但同一任务不会重复提醒。
- 用户可以查询、改期、取消和关闭主动陪伴。
- 每次行动结束后记录结果，供之后复盘；不要把沉默自动解释为同意。

## 七、建议实施顺序与验收门槛

### M1：安全边界收口

- 未知身份默认本地，不发送原话，不把未知身份绑定为家人。
- 扩充常见求助信号并覆盖多个入口。
- SafetyRouter 统一执行；严重安全行为不受普通冷却阻挡。
- 验收：测试云端调用次数、Event payload、日志、结构化告警和回复行为，而非只断言隐私标签。

### M2：统一记忆存取与恢复

- 盘点各个实际生产入口；确定权威 Event Store 和 Memory Repository。
- 让 Runtime 显式配置持久化，明确区分测试内存模式与生产持久模式。
- 实现私密记忆启动加载、TTL 清理、删除与迁移验证。
- 将 FamilyMemoryV2 的趋势视图接入 ContextBuilder 的受控查询，而不是给模型全量数据库。
- 验收：记录 → 结束进程 → 重启 → 检索成功；另一个成员无法读取 PRIVATE；删除与过期后不可再次检索。

### M3：统一任务与行动

- 把闹铃、今日四步、日常提醒逐步接入任务服务。
- 统一冷却、去重、取消、失败处理和行动回写。
- 验收：重启后任务状态正确；重复事件不重复播报；失败不能伪装成功。

### M4：生活伙伴体验

- 构建有界的生活场景工具：天气、日程、家庭待办与用户明确授权的本地动作。
- 加入记忆检索与承诺跟进，不以增加说话次数作为智能指标。
- 给家人提供轻量管理界面：记忆、权限、提醒、授权、删除与系统状态。

## 八、产品成效指标

不以“每天说了多少句话”作为成功指标。优先观察：

- 任务建立成功率、到时执行成功率、重复提醒率。
- 跨进程记忆恢复成功率、记忆检索相关性、错误回忆率。
- 用户纠正/删除记忆的成功率与耗时。
- 未识别语音云端发送率（默认目标为 0）。
- 已知安全测试集的路由覆盖率和错误升级率。
- 主动提醒被拒后，系统是否按策略降频或停止。
- Mac 连续运行稳定性与失败后恢复情况。

## 九、开发纪律

先打通一条端到端闭环，再扩展能力。每个阶段必须同时交付代码、自动化测试、隐私测试、迁移/回滚说明和 Mac 实机验收结果。

自动化测试通过不代表麦克风、蓝牙音箱、投影和 launchd 已经通过实机验收；两类结果必须分别记录。
